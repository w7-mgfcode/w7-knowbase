Hierarchical RAG

Többszintű visszakeresés: előbb összefoglalók, majd a kiválasztott szakaszok részletes darabjai. Multi-level retrieval: summaries first, then the detailed chunks of the selected sections.

01

ÁttekintésOverview

A Hierarchical RAG több réteget épít: előbb összefoglalók szintjén keres, majd a kiválasztott szakaszokon belül szűkít a részletes darabokra. Így nagy dokumentumokban is megőrzi a kontextust. Hierarchical RAG builds multiple layers: it first searches at the summary level, then narrows to detailed chunks within the selected sections — keeping context intact even in large documents.

A rétegzett index megőrzi a globális kontextust, miközben a végső válasz a pontos, részletes darabokra épül — ez csökkenti a hosszú dokumentumoknál jellemző kontextusvesztést. The layered index preserves global context while the final answer is built from precise, detailed chunks — reducing the context loss typical of long documents.

flowchart TD
  Q[User query] --> CAT[Category routing]
  CAT --> META[(Metadata index)]
  META --> FILT[Document filtering]
  FILT --> LEAF[(Leaf chunks - small pieces)]
  Q --> QEMB[Query embedding]
  QEMB --> LEAF
  LEAF --> TOPK[Top-K leaf chunks]
  TOPK --> PAR[Parent chunk retrieval - context]
  PAR --> CTX[Context assembly]
  CTX --> GEN[Generation - LLM]
  GEN --> ANS[Detailed answer with citations]

A metaadat-index irányítja a keresést a releváns kategóriára; a kis levél chunk-okban való precíz egyezés után a rendszer a szülő chunk-ot kéri le a teljes kontextusért. The metadata index routes the search to the relevant category; after precise matching in small leaf chunks the system retrieves the parent chunk for full context.

ErősségekStrengths

  • Nagy tudásbázison (5 000+ dokumentum) 90%+ keresési tér csökkentés érhető el.Achieves 90%+ search space reduction on large knowledge bases (5 000+ documents).
  • Megőrzi a dokumentum struktúráját: kis chunk = pontos embedding, szülő = teljes kontextus.Preserves document structure: small chunk = precise embedding, parent = full context.
  • Kategória-irányítás eliminálja a cross-domain zajt multi-tenant rendszerekben.Category routing eliminates cross-domain noise in multi-tenant systems.
  • Összefoglaló réteg lehetővé teszi az áttekintő és részletes kérdések kezelését is.Summary layer handles both high-level overview and detail-level questions.

KihívásokTrade-offs

  • Összetettebb indexelési pipeline: a hierarchia felépítése és karbantartása plusz munka.More complex indexing pipeline: building and maintaining the hierarchy takes extra effort.
  • A kategóriarendszer stabilitást igényel — ha sokat változik, magas a karbantartási teher.Category schema requires stability — frequently changing categories mean high maintenance cost.
  • Kis adathalmazon (5 000 dokumentum alatt) a komplexitás nem térül meg.Overhead is not justified for small corpora (under 5 000 documents).

Pro tippPro tip

Kombináld a strukturális hierarchiát (szülő-levél chunk-ok) a kategória-irányítással: a keresési tér 99%-a is kizárható, mielőtt az első vektoros összehasonlítás megtörténne — ez különösen on-call és incidens-kezelési use case-eknél adja a legjobb eredményt. Combine structural hierarchy (parent-leaf chunks) with category routing: up to 99% of the search space can be excluded before the first vector comparison — this delivers the best results in on-call and incident-response use cases.

KódpéldaCode example

hierarchical_rag_query.py 
# Build a hierarchical index with parent-child chunk relationship
from llama_index.core import VectorStoreIndex, StorageContext
from llama_index.core.node_parser import HierarchicalNodeParser, get_leaf_nodes
from llama_index.core.retrievers import AutoMergingRetriever
from llama_index.core.storage.docstore import SimpleDocumentStore

# Parse into 3-level hierarchy: 2048 → 512 → 128 tokens
node_parser = HierarchicalNodeParser.from_defaults(
    chunk_sizes=[2048, 512, 128]
)
nodes = node_parser.get_nodes_from_documents(documents)
leaf_nodes = get_leaf_nodes(nodes)

# Store all nodes so parent retrieval works at query time
docstore = SimpleDocumentStore()
docstore.add_documents(nodes)

storage_context = StorageContext.from_defaults(docstore=docstore)
index = VectorStoreIndex(leaf_nodes, storage_context=storage_context)

# AutoMergingRetriever: if >50% of sibling chunks match, return the parent
base_retriever = index.as_retriever(similarity_top_k=6)
retriever = AutoMergingRetriever(
    base_retriever,
    storage_context,
    verbose=False,
)
nodes = retriever.retrieve(question)
