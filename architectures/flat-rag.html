Flat RAG

A legegyszerűbb RAG-minta: egységes darabokra bontott korpusz, vektoros keresés, egyetlen generálási lépés. The simplest RAG pattern: a corpus split into uniform chunks, vector search, and a single generation step.

01

ÁttekintésOverview

A Flat RAG a legegyszerűbb minta: a dokumentumokat egységes méretű darabokra (chunk) bontja, vektoros beágyazásként tárolja, és egyetlen lekérdezésben a leghasonlóbb darabokat adja a generáló modellnek. Flat RAG is the simplest pattern: documents are split into uniform chunks, stored as vector embeddings, and a single query hands the most similar chunks to the generation model.

Mivel nincs többszintű logika vagy ágens, a Flat RAG gyorsan üzembe helyezhető és könnyen hibakereshető — ezért kiváló kiindulópont és összehasonlítási alap az összetettebb minták mellé. With no multi-level logic or agent, Flat RAG is fast to deploy and easy to debug — making it an excellent starting point and a baseline to compare richer patterns against.

04

AlapelvekCore Principles

A Flat RAG négy egyszerű elvre épül: lineáris, determinisztikus folyamat iteráció, osztályozás vagy útválasztás nélkül. Flat RAG rests on four simple principles: a linear, deterministic pipeline with no iteration, grading or routing.

Darabolás és tárolásChunk and store

A dokumentumokat darabokra (chunk) bontja, embeddinggé alakítja, és egy vektoradatbázisban tárolja. Documents are split into chunks, turned into embeddings, and stored in a vector database.

Egylépéses keresésSingle-shot retrieval

Egyetlen, sűrű (bi-encoder) top-k hasonlósági keresés — nincs többszöri lekérdezés. A single-shot dense (bi-encoder) top-k similarity retrieval — no repeated querying.

Egyetlen generálásSingle generation pass

A visszakapott darabokat egyetlen promptba fűzi, és egyetlen generálási lépésben adja át a modellnek. Retrieved chunks are stuffed into one prompt and handed to the model in a single generation pass.

Determinisztikus folyamatDeterministic pipeline

A folyamat lineáris és determinisztikus — nincs iteráció, osztályozás vagy útválasztás. The pipeline is linear and deterministic — no iteration, grading or routing.

06

Útválasztási stratégiaRouting Strategy

Egy útválasztó akkor küld egy lekérdezést a Flat RAG-hoz, ha az egylépéses / ténykérdés, és a válasz egyetlen darabban (chunk) megtalálható. Az Adaptive-RAG taxonómiájában ez az egylépéses visszakeresés szintje. A router sends a query to Flat RAG when it is single-hop / factual and the answer lives in one chunk. In the Adaptive-RAG taxonomy this is the single-step retrieval tier.

Mikor irányítson továbbWhen to route away

Az egylépéses visszakeresés a visszakeresés nélküli esethez képest kb. 1,4× token-költséggel jár. Több-lépéses (multi-hop) vagy globális kérdéseknél irányíts tovább Graph RAG vagy Agentic RAG felé. Single-step retrieval costs roughly 1.4× the token cost of no retrieval. Route away to Graph RAG or Agentic RAG for multi-hop or global queries.

Hibapont: a darabolásFailure mode: chunking

Iparági tapasztalatok szerint a visszakeresés az esetek nagy részében a hibapont; a fix méretű darabolás (chunking) szétszabdalja a kontextust. Egy klinikai vizsgálat témakör-igazított darabolással 87%-os, fix méretűvel 13%-os pontosságot jelentett. Industry reports put retrieval as the failure point in a large share of cases; fixed-size chunking destroys context. One clinical study reported 87% accuracy with topic-aligned chunking versus 13% with fixed-size chunking.

Mindig a baseline-hoz mérjAlways measure against the baseline

A gazdagabb architektúrákat mindig egy Flat RAG baseline-hoz mérd ugyanazon az adathalmazon — csak így derül ki, hogy a többletkomplexitás valódi nyereséget hoz-e. Always evaluate richer architectures against a Flat RAG baseline on the same dataset — only then is it clear whether the extra complexity earns its keep.

KódpéldaCode example

flat_rag_query.py 
# Build the vector store from documents
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(chunk_size=512, chunk_overlap=64)
chunks = splitter.split_documents(documents)

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma.from_documents(chunks, embeddings)

# Retriever with optional reranking
retriever = vectorstore.as_retriever(search_kwargs={"k": 6})

# RAG chain: retrieve → augment → generate
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.runnables import RunnablePassthrough

prompt = ChatPromptTemplate.from_template(
    "Answer using only the context below.\n\nContext:\n{context}\n\nQuestion: {question}"
)
llm = ChatOpenAI(model="gpt-5.4-mini")

chain = (
    {"context": retriever, "question": RunnablePassthrough()}
    | prompt
    | llm
)
response = chain.invoke(question)
