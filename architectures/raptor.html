01

ÁttekintésOverview

A RAPTOR (Recursive Abstractive Processing for Tree-Organized Retrieval) a dokumentumdarabokat klaszterezi, minden klaszterhez összefoglalót készít, és ezt rekurzívan ismétli — így egy többszintű fát épít, amelyben a lekérdezés bármely absztrakciós szinten kereshet. RAPTOR (Recursive Abstractive Processing for Tree-Organized Retrieval) clusters document chunks, summarizes each cluster, and repeats this recursively — building a multi-level tree where a query can retrieve at any level of abstraction.

A fa alsó szintjein a nyers darabok, feljebb az egyre absztraktabb összefoglalók állnak; a tematikus, korpusz-szintű kérdések a magasabb szintekről, a részletkérdések az alsókról kapnak kontextust. Raw chunks sit at the lower levels of the tree and increasingly abstract summaries above; thematic, corpus-level questions draw context from the higher levels and detail questions from the lower ones.

Az indexépítés alulról felfelé halad: a levél chunk-ok klaszterezése és összefoglalása rekurzívan ismétlődik; lekérdezéskor minden szint egy összevont vektortárból érhető el. Index construction runs bottom-up: clustering and summarisation of leaf chunks repeats recursively; at query time all levels are accessible from a single collapsed vector store.

04

AlapelvekCore Principles

A RAPTOR négy alapelvre épül: a darabok rekurzív, alulról felfelé történő absztrakciójára egy fába, amelyben a lekérdezés bármely részletességi szinten kereshet. RAPTOR rests on four principles: a recursive, bottom-up abstraction of chunks into a tree where a query can retrieve at any level of detail.

Rekurzív embed–klaszterezés–összegzésRecursive embed–cluster–summarize

A darabokat embeddinggé alakítja, klaszterezi, majd minden klaszterhez összefoglalót generál — és ezt alulról felfelé rekurzívan ismétli, amíg egyetlen gyökér marad. Chunks are embedded, clustered, then a summary is generated for each cluster — and this repeats recursively bottom-up until a single root remains.

Lágy klaszterezés (GMM + UMAP)Soft clustering (GMM + UMAP)

A Gaussian Mixture Model UMAP dimenziócsökkentéssel lágy klaszterezést végez — egy csomópont több klaszterhez is tartozhat, így az átfedő témák nem vesznek el. A Gaussian Mixture Model with UMAP dimensionality reduction performs soft clustering — a node can belong to multiple clusters, so overlapping topics are not lost.

Több absztrakciós szintMultiple abstraction levels

A fa több absztrakciós szintet tárol: a levelek kb. 100 tokenes darabok, a belső csomópontok összefoglalók, egészen egyetlen gyökérig. The tree holds multiple abstraction levels: leaves are ~100-token chunks, internal nodes are summaries, up to a single root.

Keresés tetszőleges szintenRetrieval at any level

A visszakeresés két módban történhet: összevont fa (minden csomópont laposítva, token-keretig keresve — a cikk ajánlott módja) vagy fabejárás (gyökértől levelekig leereszkedve). Retrieval runs in two modes: collapsed tree (all nodes flattened, retrieved to a token budget — the paper's recommended mode) or tree traversal (descending root to leaves).

05

Felhasználási esetekUse Cases

A RAPTOR ott a legjobb, ahol egy lekérdezésnek vagy egy elrejtett részletre, vagy egy dokumentum-szintű szintézisre lehet szüksége — hosszú dokumentumokon és tematikus kérdés-válaszhoz. RAPTOR is at its best where a query may need either a buried detail or a document-wide synthesis — on long documents and thematic Q&A.

Hosszú dokumentumok és könyvekLong documents & books

Teljes könyvek vagy hosszú narratívák (QuALITY-jellegű kérdés-válasz), ahol a kontextus a dokumentum egészéből származhat. Full books or long narratives (QuALITY-style Q&A), where context can come from the whole document.

Tudományos cikkekScientific papers

Tudományos publikációk (QASPER) és pénzügyi kutatási cikkek kérdés-válasza — részlet és összegzés egyaránt. Scientific papers (QASPER) and finance research-paper QA — both detail and synthesis.

Jogi és klinikai dokumentumokLegal & clinical documents

Klinikai vizsgálati nyilvántartások, jogi és szabályozási dokumentumok — buried detail vagy korpusz-szintű áttekintés. Clinical trial registries, legal and policy documents — a buried detail or a corpus-wide overview.

06

Útválasztási stratégiaRouting Strategy

A RAPTOR belsőleg absztrakciós szint szerint „útválaszt”: az összevont fa lehetővé teszi, hogy a hasonlósági keresés automatikusan válasszon levél- vagy összefoglaló-csomópontot. RAPTOR internally "routes" by abstraction level: the collapsed tree lets similarity search automatically pick leaf or summary nodes.

Mikor irányítson ide egy rendszer-útválasztóWhen a system router picks RAPTOR

Egy rendszerszintű útválasztó akkor irányít a RAPTOR-hoz, ha a kérdés egyetlen nagy korpusz felett egyszerre igényel finom részletet és magas szintű kontextust. A szint-alapú Adaptive RAG-ban a 2–3. szintű lekérdezések „fa-érveléshez”, azaz RAPTOR-jellegű mintához kerülnek. A system-level router picks RAPTOR when a question over a single large corpus needs both fine detail and high-level context at once. In tier-based Adaptive RAG, Tier 2–3 queries route to "tree reasoning", i.e. the RAPTOR-style pattern.

KiértékelésEvaluation

A RAPTOR kiértékelése feladat-specifikus mérőszámokat és a standard RAGAS-metrikákat ötvözi — a kulcs, hogy több absztrakciós szinten mérj. Evaluating RAPTOR combines task-specific metrics with the standard RAGAS set — the key is to measure at multiple abstraction levels.

  • Olvasásértési pontosság — QuALITY feleletválasztós.Reading-comprehension accuracy — QuALITY multiple-choice.
  • F1-érték — QASPER.F1 score — QASPER.
  • METEOR / ROUGE — NarrativeQA.METEOR / ROUGE — NarrativeQA.
  • RAGAS: kontextus-pontosság és kontextus-felidézés egyébként.RAGAS: context precision and context recall otherwise.
  • Mérj több absztrakciós szinten: levél-részlet a konkrét kérdésekhez.Evaluate at multiple abstraction levels: leaf detail for specific questions.
  • Összefoglaló-csomópontok a tematikus kérdésekhez.Summary nodes for thematic questions.
  • A belső csomópontok összefoglaló-minősége közvetlenül korlátozza a válasz minőségét.Internal-node summary quality directly bounds answer quality.

Architektúra-specifikus szempontArchitecture-specific concern

A RAPTOR akkor jó, ha minden szint jó: ha egy belső csomópont összefoglalója pontatlan vagy elnagyolt, a fölötte épülő válaszok is romlanak. Ezért az összefoglaló minőségét külön, szintenként érdemes ellenőrizni. RAPTOR is only as good as every level: if an internal node's summary is inaccurate or coarse, answers built on top of it degrade too. Summary quality should therefore be checked separately, level by level.

Pro tippPro tip

A LlamaIndex RaptorPack-kel a kód-szintű döntés az összevont fa (collapsed) és a fabejárás (tree_traversal) mód között dől el — a cikk az összevont fát ajánlja. Inkrementális RAPTOR-nál csak az érintett klasztereket és a felettük lévő összefoglalókat kell újraépíteni — nem az egész fát. Ez drasztikusan csökkenti a frissítési költséget dinamikusan növekvő korpuszok esetén. With the LlamaIndex RaptorPack the code-level decision is between the collapsed (collapsed tree) and tree_traversal modes — the paper recommends the collapsed tree. For incremental RAPTOR, rebuild only the affected clusters and their parent summaries — not the entire tree. This dramatically reduces update cost on dynamically growing corpora.

11

KódpéldaCode example

A LlamaIndex RaptorPack felépíti a fát, és lekérdezéskor a collapsed (összevont fa) vagy a tree_traversal (fabejárás) mód közül lehet választani. The LlamaIndex RaptorPack builds the tree, and at query time you choose between the collapsed (collapsed tree) and tree_traversal retrieval modes.

raptor_index_build.py 
# RAPTOR index build using LlamaIndex RaptorPack
from llama_index.packs.raptor import RaptorPack
from llama_index.core import SimpleDirectoryReader
from llama_index.llms.openai import OpenAI
from llama_index.embeddings.openai import OpenAIEmbedding

# Load corpus — works well for large document collections
documents = SimpleDirectoryReader("./corpus").load_data()

llm = OpenAI(model="gpt-5.4-mini", temperature=0)
embed_model = OpenAIEmbedding(model="text-embedding-3-small")

# Build the RAPTOR tree — clusters chunks, summarises each cluster,
# then repeats recursively until a single root summary is produced.
raptor_pack = RaptorPack(
    documents,
    llm=llm,
    embed_model=embed_model,
    summary_module=None,   # use default LLM summariser
    num_workers=4,
    # "collapsed" = flatten all nodes, retrieve to a token budget
    # (the paper's recommended mode); "tree_traversal" descends root->leaves
    mode="collapsed",
)

# Query — collapsed tree: top-K retrieved from any level simultaneously
query_engine = raptor_pack.get_modules()["query_engine"]
response = query_engine.query(
    "What recurring incident patterns appeared in the last 6 months?"
)
print(response)

# Persist the built index for reuse (avoids expensive rebuilds)
raptor_pack.get_modules()["vector_store"].persist("./raptor_index")
