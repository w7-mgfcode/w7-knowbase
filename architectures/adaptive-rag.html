Adaptive RAG

A kérdés nehézségéhez igazított keresési stratégia — olcsó út az egyszerűhöz, mély folyamat az összetetthez. Retrieval strategy matched to query difficulty — a cheap path for simple questions, a deep pipeline for complex ones.

01

ÁttekintésOverview

Az Adaptive RAG először a kérdés nehézségét osztályozza, majd ehhez illeszti a keresési stratégiát: egyszerű kérdésnél olcsó, egyenes utat választ, összetettnél több lépéses, drágább folyamatot. Adaptive RAG first classifies the difficulty of the query, then matches the retrieval strategy to it: a cheap, direct path for simple questions, a multi-step, costlier pipeline for complex ones.

Egy osztályozó előre megbecsüli a kérdés bonyolultságát, és ehhez rendel stratégiát: így a rendszer nem pazarol erőforrást egyszerű kérdésekre, és nem ad alulkutatott választ a nehezekre. A classifier estimates the complexity of the query up front and assigns a strategy — so the system neither wastes resources on easy questions nor under-researches the hard ones.

04

AlapelvekCore Principles

Az Adaptive RAG négy elvre épül: a számítási ráfordítást a kérdés nehézségéhez igazítja, lekérdezésenként. Adaptive RAG rests on four principles: it matches compute to the difficulty of the query, on a per-query basis.

Kérdés-komplexitás osztályozásaQuery-complexity classification

A keresési stratégiát egy kérdés-komplexitás osztályozó dönti el — lekérdezésenként, a feldolgozás megkezdése előtt. A query-complexity classification decides the retrieval strategy — per query, before processing begins.

Három kanonikus szintThree canonical tiers

Három kanonikus szint: visszakeresés nélkül, egylépéses visszakeresés, illetve iteratív vagy több-lépéses (multi-hop) visszakeresés. Three canonical tiers: no retrieval, single-step retrieval, and iterative or multi-hop retrieval.

Ráfordítás a nehézséghez igazítvaMatch compute to difficulty

A számítási ráfordítást a kérdés nehézségéhez igazítja — nem futtat drága folyamatot egy triviális kérdésen. Compute is matched to difficulty — it does not run an expensive pipeline on a trivial query.

Kérdéselemzés és önkorrekcióQuery analysis with self-correction

A kérdéselemzést aktív, önkorrekciós RAG-mechanizmusokkal kombinálja — a stratégia menet közben is finomodhat. It combines query analysis with active, self-corrective RAG — the strategy can refine itself on the fly.

Az Adaptive RAG ott a legerősebb, ahol a kérdések a triviálistól a több-lépésesig terjednek — vegyes terhelésű asszisztensekben. Adaptive RAG is strongest where queries range from trivial to multi-hop — in mixed-workload assistants.

06

Útválasztási stratégiaRouting Strategy

Az Adaptive RAG maga az útválasztási architektúra. Három útválasztási stílus létezik: logikai (diszkrét szabályok — fájltípus, hossz, metaadat), szemantikus (a kérdés és útválasztási minta-mondatok beágyazása, maximális koszinusz-hasonlóság — a semantic-router könyvtár; gyors, LLM-hívás nélkül), és LLM/osztályozó (egy LLM vagy finomhangolt T5/SVM címkézi a kérdés komplexitását). Adaptive RAG is the routing architecture. There are three routing styles: logical (discrete rules — file type, length, metadata), semantic (embed the query and route utterances, max cosine similarity — the semantic-router library; fast, no LLM call), and LLM/classifier (an LLM or a fine-tuned T5/SVM labels query complexity).

A kérdést egy osztályozó három útra bontja — visszakeresés nélkül, egylépéses vagy iteratív visszakeresés —, mindhárom ugyanahhoz a válaszhoz vezet. A classifier splits the query onto three paths — no retrieval, single-step or iterative retrieval — all converging on the answer.

2026-os megfigyelés: TF-IDF + SVM2026 finding: TF-IDF + SVM

A RAGRouter-Bench [paper] meglepő eredménye szerint egy klasszikus TF-IDF + SVM osztályozó felülmúlja a beágyazás-alapú útválasztókat (3,1 makró-F1 ponttal): makró-F1 0,928, 93,2%-os pontosság és 28,1%-os token-megtakarítás. Az útválasztás nem mindig igényel mély modellt. RAGRouter-Bench [paper] reports a surprising result: a classical TF-IDF + SVM classifier beats embedding-based routers (by 3.1 macro-F1) — macro-F1 0.928, 93.2% accuracy and 28.1% token savings. Routing does not always need a deep model.

KiértékelésEvaluation

Az Adaptive RAG kiértékelése két szinten zajlik: az útválasztó pontossága és a routelt válaszok végponttól végpontig vett minősége. Evaluating Adaptive RAG happens on two levels: the accuracy of the router and the end-to-end quality of the routed answers.

  • Útválasztási pontosság: az osztályozó makró-F1 / pontosság értéke címkézett kérdéstípusokon.Routing accuracy: the classifier's macro-F1 / accuracy on labeled query types.
  • Végponttól végpontig: RAGAS-metrikák a routelt válaszokon.End-to-end: RAGAS metrics on the routed answers.
  • RAGAS: kontextus-pontosság és kontextus-felidézés.RAGAS: context precision and context recall.
  • RAGAS: megalapozottság (faithfulness) és válasz-relevancia.RAGAS: faithfulness and answer relevancy.
  • Mérd a token- és költségmegtakarítást egy mindig legdrágább baseline-hoz képest.Measure token and cost savings against an always-most-expensive baseline.
  • Mérd ugyanezt egy perfekt-címke oracle-höz képest is — ez adja meg az elérhető plafont.Also measure it against a perfect-label oracle — this gives the achievable ceiling.
  • Egy rosszul kalibrált osztályozó csendben rossz útvonalra terel és rontja a pontosságot.A miscalibrated classifier silently routes to the wrong path and degrades accuracy.

KódpéldaCode example

A 2026-os standard megvalósítás egy LangGraph-gráf: egy útválasztó csomópont osztályozza a kérdést, majd feltételes élek (conditional edges) terelik a megfelelő visszakeresési ágra. The 2026 standard implementation is a LangGraph graph: a router node classifies the query, then conditional edges steer it onto the right retrieval branch.

adaptive_rag_router.py 
# pip install langgraph langchain-openai
from typing import Literal, TypedDict
from langgraph.graph import StateGraph, START, END
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field

llm = ChatOpenAI(model="gpt-5.4-mini")

class State(TypedDict):
    question: str
    answer: str

# Router node — classifies the query into one of three tiers
class Route(BaseModel):
    tier: Literal["no_retrieval", "single_step", "iterative"] = Field(
        description="Retrieval tier matched to query complexity"
    )

def classify(state: State) -> State:
    return state  # pass-through; routing decided by the edge below

def route_query(state: State) -> Literal["no_retrieval", "single_step", "iterative"]:
    decision = llm.with_structured_output(Route).invoke(
        f"Classify the retrieval tier for this query: {state['question']}"
    )
    return decision.tier

# Three retrieval strategies, one per tier
def no_retrieval(state: State) -> State:
    return {"answer": llm.invoke(state["question"]).content}

def single_step(state: State) -> State:
    docs = retriever.invoke(state["question"])
    context = "\n\n".join(d.page_content for d in docs)
    return {"answer": llm.invoke(f"Context:\n{context}\n\n{state['question']}").content}

def iterative(state: State) -> State:
    subs = llm.invoke(f"Decompose into sub-questions: {state['question']}").content
    docs = [d for q in subs.split("\n") for d in retriever.invoke(q.strip())]
    context = "\n\n".join(d.page_content for d in docs)
    return {"answer": llm.invoke(f"Context:\n{context}\n\n{state['question']}").content}

# Build the graph — conditional edges fan out from the router node
graph = StateGraph(State)
graph.add_node("classify", classify)
graph.add_node("no_retrieval", no_retrieval)
graph.add_node("single_step", single_step)
graph.add_node("iterative", iterative)
graph.add_edge(START, "classify")
graph.add_conditional_edges("classify", route_query, {
    "no_retrieval": "no_retrieval",
    "single_step": "single_step",
    "iterative": "iterative",
})
for node in ("no_retrieval", "single_step", "iterative"):
    graph.add_edge(node, END)

app = graph.compile()
result = app.invoke({"question": question})
