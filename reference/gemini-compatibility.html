01

ÁttekintésOverview

A Google Gemini API két úton érhető el. A natív API az egységes google-genai SDK-n keresztül a teljes felületet adja — contents / parts struktúra, külön system_instruction, és minden produkciós képesség (grounding, kontextus-gyorsítótár, Live API). Az OpenAI-kompatibilitási réteg ezzel szemben az OpenAI kérés/válasz sémáját tükrözi: egy meglévő OpenAI-SDK-s kódbázis pár soros változtatással Geminire állítható. Google's Gemini API is reachable two ways. The native API, through the unified google-genai SDK, exposes the full surface — the contents / parts structure, a separate system_instruction, and every production capability (grounding, context caching, the Live API). The OpenAI-compatibility layer, in contrast, mirrors OpenAI's request/response schema: an existing OpenAI-SDK codebase can be pointed at Gemini with a few-line diff.

Ugyanaz az SDK két backendet szolgál ki: a Gemini Developer API-t (API-kulcs, ingyenes szint, AI Studio — prototípushoz) és a Vertex AI-t (GCP service account + IAM — vállalati SLA-hoz és megfeleléshez). Ez az oldal a Developer API-ra fókuszál, végigveszi a 2026-os modellkínálatot, a kompat réteget és a RAG-szempontból fontos képességeket, és egy OpenAI→Gemini migrációval zár. The same SDK serves two backends: the Gemini Developer API (API key, free tier, AI Studio — for prototyping) and Vertex AI (a GCP service account + IAM — for enterprise SLAs and compliance). This page focuses on the Developer API, walks through the 2026 model lineup, the compat layer and the RAG-relevant features, and closes with an OpenAI→Gemini migration.

HitelesítésAuthentication

A kulcsot a Google AI Studio adja. A REST-hívások az x-goog-api-key: YOUR_KEY fejlécet várják; a google-genai SDK automatikusan beolvassa a GEMINI_API_KEY vagy a GOOGLE_API_KEY környezeti változót (ha mindkettő be van állítva, a GOOGLE_API_KEY nyer). A kulcs sosem kerül kliensoldali kódba — környezeti változó a fejlesztéshez, titokkezelő (secret manager) az éles környezethez, és sosem logoljuk. The key comes from Google AI Studio. REST calls expect the x-goog-api-key: YOUR_KEY header; the google-genai SDK auto-reads the GEMINI_API_KEY or GOOGLE_API_KEY environment variable (if both are set, GOOGLE_API_KEY wins). The key never goes into client-side code — an environment variable for development, a secret manager for production, and it is never logged.

Fontos változásokImportant changes

A 3.1 Pro és a 2.5 Pro rétegelt árazású: ha egy kérés promptja meghaladja a 200 000 tokent, a token-ár nagyjából megduplázódik (az egész kérésre). A Flash / Flash-Lite szintek egységárasak. A Batch API kb. 50%-kal olcsóbb, a kontextus-gyorsítótárból érkező input a sztenderd ár kb. 10%-a (a tárolás ≈ $1 / 1M token / óra). Tudásküszöb: 2025. január (3.x és 2.5 Pro). Megszűnt: a Gemini 1.5 család (2025-09), a 2.0 Flash leállítása 2026-06-01; a gemini-3-pro-preview-t a gemini-3.1-pro-preview váltotta. Gemini 3.1 Pro and 2.5 Pro are tier-priced: when a request's prompt exceeds 200,000 tokens, the per-token price roughly doubles (across the whole request). Flash / Flash-Lite tiers are flat-priced. The Batch API is ~50% cheaper, and input served from the context cache costs about 10% of the standard price (storage ≈ $1 / 1M tokens / hour). Knowledge cutoff: January 2025 (3.x and 2.5 Pro). Retired: the Gemini 1.5 family (Sept 2025), 2.0 Flash sunsetting 2026-06-01; gemini-3-pro-preview was superseded by gemini-3.1-pro-preview.

Natív SDK vs OpenAI-kompatibilitásNative SDK vs OpenAI compatibility

A két belépési pont nem egyenrangú. A natív SDK a teljes Gemini felületet adja; az OpenAI-kompat réteg egy hordozhatósági réteg, amellyel egy meglévő OpenAI-pipeline gyorsan átköltöztethető. The two entry points are not equals. The native SDK exposes the full Gemini surface; the OpenAI-compat layer is a portability shim that moves an existing OpenAI pipeline over fast.

Kompatibilis ≠ teljesCompatible ≠ complete

Az OpenAI-kompat réteg hivatalosan béta; csak a /chat/completions támogatott — az OpenAI /responses végpontja nem (404-et ad). Az ismeretlen paramétereket a réteg csendben eldobja (a seed például nem érvényesül), egyes válaszmezők (system_fingerprint, service_tier) hiányoznak, a JSON Schema csak részhalmazként támogatott, és az érvelés a Pro / 3.x modelleken nem kapcsolható ki teljesen. Produkciós Gemini-munkához — grounding, natív gyorsítótárazás, teljes thinking-vezérlés, Live API — a natív google-genai SDK kell. The OpenAI-compat layer is officially beta; only /chat/completions is supported — OpenAI's /responses endpoint is not (it 404s). Unknown parameters are silently dropped (seed, for instance, is not honored), some response fields (system_fingerprint, service_tier) are omitted, JSON Schema is supported only as a subset, and reasoning cannot be fully disabled on the Pro / 3.x models. Production Gemini work — grounding, native caching, full thinking control, the Live API — needs the native google-genai SDK.

StreamingStreaming

A streaming a választ tokenekre bontva, valós időben adja vissza — a felhasználó az első tokent töredék idő alatt látja. A natív SDK egy dedikált generate_content_stream metódust ad; iteráláskor a chunk.text hordozza a szövegtöredéket. Streaming returns the response in real time, broken into tokens — the user sees the first token in a fraction of the time. The native SDK provides a dedicated generate_content_stream method; while iterating, chunk.text carries the text fragment.

gemini_streaming.py
# pip install google-genai
from google import genai

client = genai.Client()  # reads GEMINI_API_KEY / GOOGLE_API_KEY

stream = client.models.generate_content_stream(
    model="gemini-3-flash-preview",
    contents="Explain RAG in three short sentences.",
)
for chunk in stream:
    print(chunk.text, end="", flush=True)

REST és többfordulós chatREST & multi-turn chat

REST-en a streaming a :streamGenerateContent?alt=sse végponton érhető el, Server-Sent Events formában. Többfordulós beszélgetéshez a client.chats.create(...) + chat.send_message(...) segédfelület tartja a kontextust; ennek is van streamelő változata. A streaming hibakezelése nehezebb: a folyam közben fellépő hibára is fel kell készülni. Over REST, streaming is available on the :streamGenerateContent?alt=sse endpoint as Server-Sent Events. For multi-turn conversations the client.chats.create(...) + chat.send_message(...) helper holds the context; it has a streaming variant too. Error handling is harder when streaming: a failure mid-stream must also be handled.

Function calling és eszközökFunction calling & tools

A function calling során a modell strukturált JSON-t állít elő egy általunk leírt függvény meghívásához. A deklarációk az OpenAPI 3.0.3 egy részhalmazát használják; a Python SDK ezen felül automatikus function callingot is kínál. In function calling the model produces structured JSON to invoke a function we describe. Declarations use a subset of OpenAPI 3.0.3; the Python SDK additionally offers automatic function calling.

automatic_fc.py
# Automatic function calling — Python SDK only
def get_weather(location: str) -> dict:
    """Get current weather for a city."""
    return {"location": location, "tempC": 21}

resp = client.models.generate_content(
    model="gemini-3-flash-preview",
    contents="Weather in Budapest?",
    config={"tools": [get_weather]},  # SDK runs the loop
)
print(resp.text)

Hívási módokCalling modes

A tool_config.function_calling_config mód lehet AUTO (a modell dönt), ANY (kötelező hívnia), VALIDATED (alapértelmezett eszközkombinációknál; kikényszeríti a sémát) vagy NONE. Az automatikus function calling csak a Python SDK-ban: sima, típusozott, docstringgel ellátott függvényeket adunk át tools-ként, és az SDK generálja a deklarációt és lefuttatja a hívás→válasz kört (AutomaticFunctionCallingConfig(disable=True) kapcsolja ki). Kézi körben a modell egy function_call részt ad vissza, amire egy types.Part.from_function_response(...)-szel válaszolunk. The tool_config.function_calling_config mode can be AUTO (the model decides), ANY (it must call), VALIDATED (the default for tool combinations; it enforces the schema) or NONE. Automatic function calling is Python-SDK-only: pass plain typed functions with docstrings as tools, and the SDK generates the declaration and runs the call→response loop (AutomaticFunctionCallingConfig(disable=True) turns it off). In a manual loop the model returns a function_call part, which you answer with a types.Part.from_function_response(...).

Strukturált kimenetekStructured outputs

A strukturált kimenet egy megadott sémához köti a modell válaszát. A Geminiben ezt a response_mime_type és a response_schema konfigurációs mezők vezérlik; a Python SDK Pydantic-modellt vagy típusannotációt is elfogad sémaként. Structured output binds the model's response to a supplied schema. In Gemini this is driven by the response_mime_type and response_schema config fields; the Python SDK also accepts a Pydantic model or a type annotation as the schema.

structured_output.py
from pydantic import BaseModel

class Cat(BaseModel):
    name: str
    colour: str

resp = client.models.generate_content(
    model="gemini-3-flash-preview",
    contents="Generate 3 cats.",
    config={
        "response_mime_type": "application/json",
        "response_schema": list[Cat],
    },
)
my_cats = resp.parsed  # typed objects; resp.text is raw JSON

SémaszabályokSchema rules

A lapos response_mime_type / response_schema alak a régóta bevált, széles körben használt forma. A resp.parsed a típusos objektumokat adja, a resp.text a nyers JSON-stringet. Enum-kimenethez a response_mime_type="text/x.enum" használható. Támogatott típusok: string / number / integer / boolean / object / array / null, plusz enum, format, min/max stb. — de nem minden JSON Schema-jellemző támogatott: a nem támogatott tulajdonságokat a modell figyelmen kívül hagyja. The flat response_mime_type / response_schema form is the long-standing, widely used shape. resp.parsed yields the typed objects, resp.text the raw JSON string. For enum output, use response_mime_type="text/x.enum". Supported types: string / number / integer / boolean / object / array / null, plus enum, format, min/max, etc. — but not all JSON Schema features are supported: the model ignores unsupported properties.

09

RAG-szempontból fontos képességekRAG-relevant features

A Gemini API néhány olyan képessége közvetlenül érinti a RAG-rendszerek tervezését — a hosszú kontextustól a gyorsítótárazáson át a search groundingig és az embeddingsig. A handful of Gemini API capabilities bear directly on how RAG systems are designed — from long context through caching to search grounding and embeddings.

Hosszú kontextusLong context

1M+ tokenes ablakok (a 3.1 Pro akár ~2M-ig). Megengedi a „kontextusba töltést” retrieval helyett — de a többtűs visszakeresés romlik, és a 200k feletti prompt a Pro árszintet hozza. A kérdést tedd a prompt végére. 1M+ token windows (3.1 Pro up to ~2M). Allows "stuffing the context" instead of retrieval — but multi-needle recall degrades, and a prompt above 200k triggers the Pro price tier. Put the question at the end of the prompt.

Kontextus-gyorsítótárContext caching

Implicit (automatikus a 2.5+ modelleken, prefix-egyezés) vagy explicit (client.caches.create(...), garantált kedvezmény). A gyorsítótárazott input ≈ 10% ár; ez a hosszú kontextusú RAG fő költségkarja. Implicit (automatic on 2.5+ models, prefix-match) or explicit (client.caches.create(...), a guaranteed discount). Cached input costs ≈ 10%; this is the main cost lever for long-context RAG.

Grounding + URL-kontextusGrounding + URL context

A Google Search grounding eszköz grounding_metadata-t ad (forrás-URL-ek, idézet-térkép). A friss, nyilvános webes kérdéseknél kiválthat egy vektortárat — privát korpuszhoz nem. Plusz egy URL-kontextus eszköz (≤20 URL). The Google Search grounding tool returns grounding_metadata (source URLs, a citation map). For fresh, public-web questions it can replace a vector store — not for a private corpus. Plus a URL-context tool (≤20 URLs).

EmbeddingsEmbeddings

gemini-embedding-001 (szöveg) és gemini-embedding-2 (multimodális). Matryoshka (MRL) dimenziók — alapból 3072, levágható 768/1536-ra. Illeszd a feladattípust: RETRIEVAL_DOCUMENT a chunkokhoz, RETRIEVAL_QUERY a lekérdezésekhez. gemini-embedding-001 (text) and gemini-embedding-2 (multimodal). Matryoshka (MRL) dimensions — 3072 by default, truncatable to 768/1536. Match the task type: RETRIEVAL_DOCUMENT for chunks, RETRIEVAL_QUERY for queries.

Batch APIBatch API

Aszinkron feldolgozás, kb. 50%-os költség, ~24 órás átfutás. Korpusz-embeddinghez, újra-összegzéshez és RAG-kiértékelő futtatásokhoz való — nem interaktív kiszolgáláshoz. Asynchronous processing, ~50% cost, ~24h turnaround. For corpus embedding, re-summarization and RAG eval runs — not for interactive serving.

ThinkingThinking

A thinking_config a thinking_budget-tel szabályozza a gondolkodást (-1 = dinamikus; 0 csak Flashen tiltja). A thinking-tokenek kimenetként számláznak — extraktív RAG-hoz korlátozd, többlépcsős szintézishez tartsd meg. The thinking_config governs reasoning via thinking_budget (-1 = dynamic; 0 disables on Flash only). Thinking tokens bill as output — cap them for extractive RAG, keep them for multi-hop synthesis.

Hosszú kontextus vs retrievalLong context vs retrieval

A milliós ablak nem szünteti meg a retrievalt. Egytűs keresésben a pontosság ~99%, de többtűs visszakeresésnél romlik, a hosszú input növeli az első tokenig tartó időt, és 200k token felett belép a drágább árszint. A bevált minta: szűkíts retrievallel, majd a kiválasztott kontextust töltsd be — a gyorsítótárral a stabil prefixet ≈ 10% áron tartva. A multimodális bemenethez a nagy/újrahasznált fájlokat a File API-n keresztül töltsd fel (fájlonként ≤2 GB, 48 órás megőrzés). A million-token window does not remove retrieval. Single-needle accuracy is ~99%, but multi-needle recall degrades, long input raises time-to-first-token, and above 200k tokens the costlier price tier kicks in. The proven pattern: narrow with retrieval, then load the selected context — keeping the stable prefix at ≈ 10% cost via caching. For multimodal input, upload large/reused files through the File API (≤2 GB per file, 48h retention).

A natív Gemini API alakja több ponton eltér az OpenAI-étól. A kompat réteg ezeket elfedi a gyors migrációhoz; a natív felület átvételekor viszont számolni kell velük. Migrációs tippMigration tip

A gyors út: állítsd az OpenAI SDK base_url-jét a Gemini kompat rétegre, és a meglévő pipeline pár soros változtatással fut. Ez azonban béta, és a /responses-re épülő kód nem hordozható. A második lépésben térj át a natív google-genai SDK-ra ott, ahol produkciós képesség kell — grounding, natív gyorsítótár, teljes thinking-vezérlés. Az érvelés a Pro / 3.x modelleken nem kapcsolható ki teljesen; a thinking_budget-tel hangolható. The fast path: set the OpenAI SDK's base_url to the Gemini compat layer, and the existing pipeline runs with a few-line diff. That layer is beta, though, and code built on /responses is not portable. As a second step, move to the native google-genai SDK wherever a production capability is needed — grounding, native caching, full thinking control. Reasoning cannot be fully disabled on the Pro / 3.x models; it is tuned with thinking_budget.

KöltségkarokCost levers

A kontextus-gyorsítótárazott input ≈ 10% ár; a Batch API ≈ 50%-kal olcsóbb; a 3.1 / 2.5 Pro 200k token felett dupla árú. Hosszú, ismételt kontextust gyorsítótárazz, kötegelhető munkát a Batch API-ra tegyél. Context-cached input costs ≈ 10%; the Batch API is ≈ 50% cheaper; 3.1 / 2.5 Pro double in price above 200k tokens. Cache long, repeated context, and route batchable work to the Batch API.

RAG-útmutatóRAG guidance

Szűkíts retrievallel, majd töltsd be a kiválasztott kontextust; a friss, nyilvános webes kérdéseket grounding fedi, a privát korpuszt vektortár. Embeddinghez illeszd a feladattípust, korpusz-feldolgozáshoz használj Batch API-t. Narrow with retrieval, then load the selected context; cover fresh public-web questions with grounding, a private corpus with a vector store. Match the task type for embeddings, and use the Batch API for corpus processing.

BiztonságSecurity

Soha ne égess be kulcsot, és ne küldd kliensre. Fejlesztéshez környezeti változó, éleshez titokkezelő. A kulcsot sose logold. Egy biztonsági blokk üres tartalmat ad — mindig nézd a finishReason-t. Never hardcode a key, never ship it to the client. An environment variable for dev, a secret manager for prod. Never log the key. A safety block returns empty content — always inspect finishReason.

KódpéldaCode example

A natív google-genai SDK adja a teljes felületet; ugyanakkor a sztenderd OpenAI SDK is hív Geminit, ha a base_url-t a kompat rétegre állítjuk — ez a migráció gyors útja. The native google-genai SDK gives the full surface; the standard OpenAI SDK also calls Gemini when base_url is set to the compat layer — the fast path for migration.

gemini_quickstart.py 
# pip install google-genai openai

# --- Native API: the full Gemini surface ---------------------------
from google import genai

client = genai.Client()  # reads GEMINI_API_KEY / GOOGLE_API_KEY
resp = client.models.generate_content(
    model="gemini-3-flash-preview",
    contents="Explain RAG in one sentence.",
    config={"system_instruction": "You are a concise assistant."},
)
print(resp.text)

# --- Native streaming ----------------------------------------------
for chunk in client.models.generate_content_stream(
    model="gemini-3-flash-preview",
    contents="List three RAG architectures.",
):
    print(chunk.text, end="", flush=True)

# --- Same OpenAI SDK, pointed at the Gemini compat layer -----------
# Only base_url + api_key change; great for a fast migration.
from openai import OpenAI

compat = OpenAI(
    api_key="GEMINI_API_KEY",
    base_url="https://generativelanguage.googleapis.com/v1beta/openai/",
)
chat = compat.chat.completions.create(
    model="gemini-3-flash-preview",
    messages=[{"role": "user", "content": "Hello from the compat layer!"}],
)
print(chat.choices[0].message.content)
