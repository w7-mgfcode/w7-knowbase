01

ÁttekintésOverview

Egy RAG rendszer minősége két egymástól független ponton dől el: a visszakeresési (retrieval) lépésnél és a generálási lépésnél. A visszakeresés hibái — releváns dokumentumok kihagyása, irrelevánsak bevonása — nem javíthatók utólag a generáló modellel. Ezért a két szintet külön is mérni kell: egy összesített „helyes válasz" arány elfedi, hogy melyik komponens rontott le. A RAG system's quality is decided at two independent points: the retrieval step and the generation step. Retrieval failures — missing relevant documents, including irrelevant ones — cannot be corrected by the generation model. That is why both levels must be measured independently: an aggregate "correct answer" rate hides which component degraded.

A 2026-os gyakorlatban a RAGAS és hasonló keretrendszerek (DeepEval, TruLens, Arize Phoenix) LLM-as-a-judge megközelítéssel értékelik a hűséget (faithfulness/groundedness), a válasz relevanciáját és a kontextus relevanciáját. Az offline kiértékelést arany teszthalmazon futtatják, az online kiértékelés pedig valós felhasználói forgalmon alapul. In 2026 practice, RAGAS and similar frameworks (DeepEval, TruLens, Arize Phoenix) apply an LLM-as-a-judge approach to measure faithfulness/groundedness, answer relevance, and context relevance. Offline evaluation runs on a golden test set; online evaluation operates on real user traffic.

04

Gyakorlati tanácsokPractical guidance

Helyes gyakorlatokBest practices

  • Építs arany teszthalmazt a Day 1-től: legalább 100-200 kérdés-válasz-forrás hármas, amelyet emberi szakértők hitelesítenek.Build a golden test set from Day 1: at least 100-200 question-answer-source triples validated by human experts.
  • Mérj visszakeresést és generálást külön-külön — egy összesített pontszám elfedi a valódi problémaforrást.Measure retrieval and generation separately — an aggregate score hides the true failure source.
  • Használj LLM-as-a-judge megközelítést hűségmérésre (RAGAS faithfulness), de validáld emberi mintán is.Use an LLM-as-a-judge approach for faithfulness measurement (RAGAS faithfulness), but validate on a human sample too.
  • Online kiértékeléshez figyeld az implicit jelzéseket: újraindított kérdések, visszajelzés-gombok, munkamenet-elhagyás.For online evaluation, track implicit signals: rephrased follow-up questions, thumbs feedback, session abandonment.

Tipikus csapdákCommon pitfalls

  • Az arany teszthalmaz ugyanabból a forrásból kerül ki, mint az indexelt dokumentumok — adatszivárgás veszélye.The golden test set is drawn from the same source as indexed documents — risk of data leakage.
  • Az LLM-bíró önmaga hallucináló ítéleteket hozhat — minden bírói LLM egy forrásból fakad.The LLM judge can itself produce hallucinated judgements — every judge LLM has the same failure mode.
  • Csak offline metrikákat nézni: a produkciós eloszlás eltérhet a teszthalmaztól (distribution shift).Watching only offline metrics: the production distribution may drift from the test set (distribution shift).
  • Egyetlen átlagos pontszámra hagyatkozni ahelyett, hogy a legrosszabb eseteket (tail failures) vizsgálnánk.Relying on a single average score instead of investigating the worst-case tail failures.

A RAGAS négy fő metrikájaRAGAS four core metrics

A RAGAS keretrendszer négy metrikát számít: (1) Faithfulness — a válasz állításai mennyire alapulnak a visszakeresett kontextuson; (2) Answer Relevancy — a válasz mennyire releváns az eredeti kérdéshez; (3) Context Precision — a visszakeresett dokumentumok mekkora hányada valóban releváns; (4) Context Recall — a releváns információ mekkora hányadát sikerült visszakeresni. Mindegyiket LLM-as-a-judge pontja, ezért determinisztikusan nem reprodukálhatók, de statisztikailag stabil metrikák. RAGAS computes four metrics: (1) Faithfulness — how well the answer's claims are grounded in the retrieved context; (2) Answer Relevancy — how relevant the answer is to the original question; (3) Context Precision — what fraction of the retrieved documents are actually relevant; (4) Context Recall — what fraction of the relevant information was retrieved. Each is scored by an LLM judge, so they are not deterministically reproducible, but are statistically stable metrics.

KódpéldaCode example

rag_evaluation.py 
# RAG evaluation with RAGAS (ragas>=0.2) + a custom retrieval metric pass
from ragas import evaluate
from ragas.metrics import (
    faithfulness,
    answer_relevancy,
    context_precision,
    context_recall,
)
from ragas.llms import LangchainLLMWrapper
from datasets import Dataset
from langchain_openai import ChatOpenAI


# --- Build the evaluation dataset -----------------------------------
# Each row: question, ground_truth answer, retrieved contexts, generated answer.
# 'contexts' is a list[str] of the chunks the RAG pipeline returned.
eval_data = {
    "question":      ["What is Reciprocal Rank Fusion?", ...],
    "ground_truth":  ["RRF merges ranked lists by ...", ...],
    "contexts":      [["chunk A text", "chunk B text"], ...],
    "answer":        ["RRF is a score fusion method that ...", ...],
}
dataset = Dataset.from_dict(eval_data)


# --- Configure the judge LLM ----------------------------------------
judge_llm = LangchainLLMWrapper(ChatOpenAI(model="gpt-4o-mini", temperature=0))

metrics = [faithfulness, answer_relevancy, context_precision, context_recall]
for m in metrics:
    m.llm = judge_llm


# --- Run RAGAS evaluation -------------------------------------------
results = evaluate(dataset=dataset, metrics=metrics)
df = results.to_pandas()
print(df[["faithfulness", "answer_relevancy",
          "context_precision", "context_recall"]].describe())


# --- Standalone retrieval metrics (no judge LLM needed) -------------
def retrieval_recall(retrieved_ids: list[str], relevant_ids: set[str]) -> float:
    """Fraction of relevant documents that were actually retrieved."""
    if not relevant_ids:
        return 0.0
    hits = sum(1 for doc_id in retrieved_ids if doc_id in relevant_ids)
    return hits / len(relevant_ids)

def ndcg_at_k(retrieved_ids: list[str], relevant_ids: set[str], k: int = 10) -> float:
    """nDCG@k: penalises relevant docs appearing lower in the ranking."""
    import math
    dcg = sum(
        1.0 / math.log2(rank + 2)
        for rank, doc_id in enumerate(retrieved_ids[:k])
        if doc_id in relevant_ids
    )
    ideal = sum(
        1.0 / math.log2(rank + 2)
        for rank in range(min(len(relevant_ids), k))
    )
    return dcg / ideal if ideal else 0.0
