01

ÁttekintésOverview

Az embedding modellek szövegeket sűrű numerikus vektorokká alakítanak, amelyekben a szemantikailag hasonló szövegek közel kerülnek egymáshoz a vektortérben. RAG rendszerekben az embedding minősége közvetlenül meghatározza a visszakeresés pontosságát: gyenge embedding esetén még a legjobb reranker sem tud kármenteni. A 2026-os modellgeneráció — Qwen3-Embedding, Voyage 4, Gemini Embedding 2 — LLM-gerincű architektúrákat, Matryoshka (MRL) dimenziócsökkentést, kvantizálás-tudatos tanítást és multimodális vektortereket hoz. Embedding models convert text into dense numerical vectors where semantically similar texts cluster close together in the vector space. In RAG systems, embedding quality directly determines retrieval accuracy: even the best reranker cannot fully compensate for a weak embedding. The 2026 model generation — Qwen3-Embedding, Voyage 4, Gemini Embedding 2 — brings LLM-backbone architectures, Matryoshka (MRL) dimension reduction, quantization-aware training, and multimodal vector spaces.

Az iparági értékelési eszköz az MTEB, amelynek leaderboardja ma alapból a többnyelvű MMTEB rangsort mutatja, külön angol (MTEB eng v2) és legacy v1 fülekkel. RAG-hoz a Retrieval alkategória a meghatározó — az összesített pontszám félrevezető lehet. A dense modellek mellett terjednek a sparse (lexikai) és a ColBERT-stílusú late-interaction megközelítések is. (Adatpillanat: 2026. május.) The industry evaluation tool is MTEB, whose leaderboard now defaults to the multilingual MMTEB ranking, with separate English (MTEB eng v2) and legacy v1 tabs. For RAG the Retrieval sub-category is what matters — the aggregate score can be misleading. Alongside dense models, sparse (lexical) and ColBERT-style late-interaction approaches are also gaining ground. (Data snapshot: May 2026.)

Matryoshka (MRL)Matryoshka (MRL)

  • A fontos információ a vezető dimenziókban koncentrálódik, így a vektor egyszerűen csonkítható.The important information is concentrated in the leading dimensions, so the vector can simply be truncated.
  • 3072→768d csonkítás kb. <10% recall-veszteséget okoz; a 256d a gyakori „agresszív, de használható” alsó határ.Truncating 3072→768d costs roughly <10% recall; 256d is the common "aggressive but usable" floor.
  • Ma gyakorlatilag univerzális: OpenAI 3-large/small, Gemini, Cohere v4, Voyage 4, Jina, Qwen3, Nomic, EmbeddingGemma.Now effectively universal: OpenAI 3-large/small, Gemini, Cohere v4, Voyage 4, Jina, Qwen3, Nomic, EmbeddingGemma.

KvantizálásQuantization

  • Precíziós létra: float32 → float16 → int8 → binary, egyre kisebb tárhellyel.Precision ladder: float32 → float16 → int8 → binary, with progressively smaller storage.
  • A kvantizálás-tudatos tanítás (QAT) a 2025–2026-os váltás: a modell már a kvantizálással együtt tanul.Quantization-aware training (QAT) is the 2025–2026 shift: the model trains with quantization in the loop.
  • A Voyage API-paraméterként kínál float32/int8/uint8/binary-t; a Cohere v4 és a Jina támogatja a binaryt. A gyártó szerint a voyage-context-3 binary/512d az OpenAI-3-large float/3072d szintjét hozza.Voyage exposes float32/int8/uint8/binary as an API parameter; Cohere v4 and Jina support binary. Vendor-reported: voyage-context-3 binary/512d matches OpenAI-3-large float/3072d.

Tárhely-számításStorage calculation

1024 dimenziós vektorok, 250M darab (Sentence-Transformers referencia): float32 ≈ 954 GB → int8 ≈ 238 GB (4×, ~99.3% pontosság-megtartás, rescore nélkül) → binary ≈ 30 GB (32×, ~92.5% rescore nélkül, ~96% rescore-ral). 1024-dimension vectors, 250M of them (Sentence-Transformers reference): float32 ≈ 954 GB → int8 ≈ 238 GB (4×, ~99.3% retention, no rescore) → binary ≈ 30 GB (32×, ~92.5% no rescore, ~96% with rescore).

Kontextualizált chunk-embeddingContextualized chunk embedding

Három párhuzamos megközelítés: (1) Anthropic Contextual Retrieval — LLM minden chunk elé kontextus-leírást fűz; (2) késői chunkolás (Jina) — előbb az egész dokumentum embedingje, majd felosztás és pooling; (3) voyage-context-3 — a modell tanulja be a globális dokumentum-kontextust minden chunk-vektorba, per-chunk LLM-hívás nélkül. A gyártó szerint a voyage-context-3 +6.76%-ot hoz az Anthropic Contextual Retrievalhez képest. Three coexisting approaches: (1) Anthropic Contextual Retrieval — an LLM prepends a context blurb to each chunk; (2) late chunking (Jina) — embed the whole document first, then split and pool; (3) voyage-context-3 — the model is trained to inject global document context into each chunk vector, with no per-chunk LLM call. Vendor-reported: voyage-context-3 is +6.76% over Anthropic Contextual Retrieval.

# Dense embedding with MRL dimension reduction (Matryoshka)
from openai import OpenAI

client = OpenAI()

def embed_texts(texts: list[str], dimensions: int = 512) -> list[list[float]]:
    # text-embedding-3-small supports MRL: reduce from 1536d to any lower value
    response = client.embeddings.create(
        model="text-embedding-3-small",
        input=texts,
        dimensions=dimensions,   # MRL: 256 / 512 / 768 / 1536
    )
    return [item.embedding for item in response.data]
