ÁttekintésOverview

Az embedding modellek szövegeket sűrű numerikus vektorokká alakítanak, amelyekben a szemantikailag hasonló szövegek közel kerülnek egymáshoz a vektortérben. RAG rendszerekben az embedding minősége közvetlenül meghatározza a visszakeresés pontosságát: gyenge embedding esetén még a legjobb reranker sem tud kármenteni. A 2026-os modellgeneráció — Qwen3-Embedding, NV-Embed-v2, Cohere embed-v4 — 7B+ paraméteres decoder-only architektúrákat és Matryoshka Representation Learning (MRL) dimenziócsökkentést hoz. Embedding models convert text into dense numerical vectors where semantically similar texts cluster close together in the vector space. In RAG systems, embedding quality directly determines retrieval accuracy: even the best reranker cannot fully compensate for a weak embedding. The 2026 model generation — Qwen3-Embedding, NV-Embed-v2, Cohere embed-v4 — brings 7B+ parameter decoder-only architectures and Matryoshka Representation Learning (MRL) dimension reduction.

Az iparági standard értékelési eszköz az MTEB (Massive Text Embedding Benchmark), amely 8 feladattípuson, 58 adatkészleten és 112 nyelven méri a modelleket. RAG-hoz a Retrieval alkategória a meghatározó — az összesített MTEB-pontszám félrevezető lehet, ha egy modell klaszterezésben kiemelkedő, de visszakeresésben gyengébb. A dense modellek mellett terjednek a sparse (BM25-szerű) és a ColBERT-stílusú late-interaction megközelítések is. The industry-standard evaluation tool is MTEB (Massive Text Embedding Benchmark), which measures models across 8 task types, 58 datasets, and 112 languages. For RAG the Retrieval sub-category is what matters — the overall MTEB score can be misleading if a model excels at clustering but underperforms at retrieval. Alongside dense models, sparse (BM25-like) and ColBERT-style late-interaction approaches are also gaining ground.

Gyakorlati tanácsokPractical guidance

Bevált megközelítésekProven approaches

  • MRL-kompatibilis modell választásakor kezdj kisebb dimenzióval (pl. 512d), és csak szükség esetén növeld — a tárhely és sebesség javul minimális minőségvesztéssel.When choosing an MRL-compatible model, start with a smaller dimension (e.g. 512d) and increase only if needed — storage and speed improve with minimal quality loss.
  • MTEB Retrieval alkategóriát nézd, ne az összesített átlagot RAG értékeléshez.Look at the MTEB Retrieval sub-category, not the overall average, when evaluating for RAG.
  • Kezdő projekthez az OpenAI text-embedding-3-small ideális: $0.02/1M token, 1536d, kiváló ökoszisztéma-integráció.For a starter project, OpenAI text-embedding-3-small is ideal: $0.02/1M tokens, 1536d, excellent ecosystem integration.
  • Többnyelvű adatnál BGE-M3 (open-source, 100+ nyelv) vagy Cohere embed-v4 (API, 128K kontextus).For multilingual data, use BGE-M3 (open-source, 100+ languages) or Cohere embed-v4 (API, 128K context).

Gyakori hibákCommon pitfalls

  • Legacy ada-002 használata: rosszabb ár/teljesítmény arány, mint az újabb 3-small modell esetén.Using legacy ada-002: worse price/performance ratio than the newer 3-small model.
  • 7B+ modell CPU-n futtatása: érdemi sebesség nem érhető el, GPU szükséges.Running a 7B+ model on CPU: meaningful speed is not achievable, a GPU is required.
  • Modell kiválasztása saját adat nélküli benchmark alapján: mindig mérj a saját domainjeden!Selecting a model based on benchmarks without testing on your own data: always evaluate on your own domain!
  • Aszimmetrikus embedding kihagyása: a query és a dokumentum különböző instrukciós prefixet igényelhet.Skipping asymmetric embedding: query and document may require different instruction prefixes.

Fine-tuning mikor éri meg?When is fine-tuning worth it?

Domain-specifikus fine-tuning 10–30%-os visszakeresési javulást adhat jogi, orvosi vagy műszaki szövegkorpuszon. Sentence Transformers könyvtárral és néhány ezer (kérdés, releváns dokumentum) párral elegendő. Alternatíva: instrukció-hangolt modell (Qwen3-Embedding, E5-Mistral) természetes nyelvű prefixszel — fine-tuning nélkül. Domain-specific fine-tuning can yield 10–30% retrieval improvement on legal, medical, or technical corpora. Sentence Transformers library with a few thousand (query, relevant document) pairs is sufficient. Alternative: instruction-tuned model (Qwen3-Embedding, E5-Mistral) with a natural-language prefix — no fine-tuning needed.

# pip install sentence-transformers openai
# Dense embedding with MRL dimension reduction (Matryoshka)
from openai import OpenAI

client = OpenAI()

def embed_texts(texts: list[str], dimensions: int = 512) -> list[list[float]]:
    # text-embedding-3-small supports MRL: reduce from 1536d to any lower value
    response = client.embeddings.create(
        model="text-embedding-3-small",
        input=texts,
        dimensions=dimensions,   # MRL: 256 / 512 / 768 / 1536
    )
    return [item.embedding for item in response.data]

# Open-source alternative: BGE-M3 with dense + sparse modes
from FlagEmbedding import BGEM3FlagModel

model = BGEM3FlagModel("BAAI/bge-m3", use_fp16=True)

def embed_bge(texts: list[str]) -> dict:
    # Returns dense, sparse (lexical), and colbert_vecs
    return model.encode(
        texts,
        batch_size=12,
        max_length=8192,
        return_dense=True,
        return_sparse=True,
        return_colbert_vecs=False,
    )

# Instruction-tuned model: Qwen3-Embedding with task prefix
from sentence_transformers import SentenceTransformer

qwen = SentenceTransformer("Alibaba-NLP/gte-Qwen3-8B-instruct", trust_remote_code=True)

query_vecs = qwen.encode(
    ["What is Matryoshka Representation Learning?"],
    prompt_name="query",          # asymmetric: query vs. passage prefix
)
doc_vecs = qwen.encode(
    ["MRL trains nested representations..."],
    prompt_name="passage",
)
