Hibrid keresésHybrid Search

01

ÁttekintésOverview

A hagyományos vektoros keresés a szemantikai hasonlóságra támaszkodik: a kérdés és a dokumentumdarabok embedding-vektorait hasonlítja össze a vektortérben. Kiváló az általános, parafrazált kérdéseknél, de megbukhat pontos kulcsszavaknál, kódneveken, termékszámokon vagy speciális szakkifejezéseken — ahol a BM25-alapú ritka visszakeresés megbízhatóbb. Traditional vector search relies on semantic similarity: it compares the embedding vectors of the query and document chunks in vector space. It excels at paraphrased, general questions, but can fail on exact keywords, codenames, product numbers, or highly specific terms — where BM25-based sparse retrieval is more reliable.

A hibrid keresés mindkét módszert párhuzamosan futtatja, majd a találati listákat egy pontszám-összefűző (score fusion) algoritmussal — tipikusan Reciprocal Rank Fusion (RRF) vagy súlyozott összeg — vonja össze. Az eredmény egy olyan rangsorolt lista, amely a szemantikai és kulcsszavas relevanciát egyaránt figyelembe veszi, így szinte minden lekérdezési stílusnál felülmúlja a csak vektoros megközelítést. Hybrid search runs both methods in parallel, then merges the result lists using a score fusion algorithm — typically Reciprocal Rank Fusion (RRF) or a weighted sum. The result is a ranked list that captures both semantic and keyword relevance, consistently outperforming pure-vector approaches across virtually all query styles.

KompromisszumokTrade-offs

  • Két indexet kell fenntartani és szinkronban tartani, ami növeli az infrastrukturális terhet.Two indexes must be maintained and kept in sync, increasing infrastructure overhead.
  • Az alfa-paraméter hangolása (dense vs. sparse arány) kísérleti optimalizálást igényel.Tuning the alpha parameter (dense vs. sparse weight) requires experimental optimisation.
  • Az RRF k-konstansa (jellemzően 60) befolyásolja, mennyire bünteti az alacsony helyezéseket; helytelen beállítás rontja a fúziót.The RRF k-constant (typically 60) controls how harshly low ranks are penalised; misconfiguration degrades fusion quality.
  • A lekérdezési késleltetés megnőhet, ha a két keresési útvonal nem fut valóban párhuzamosan.Query latency increases if the two retrieval paths are not run in true parallel.

RRF-képletRRF formula

Az RRF pontszám minden dokumentumra: RRF(d) = 1/(k + rank_dense(d)) + 1/(k + rank_sparse(d)), ahol k = 60 az alapértelmezett konstans. A képlet a jó helyezés jutalmát halmozza össze, nem az eredeti pontszámot — így a két rendszer eltérő skálájú pontszámai sem okoznak torzítást. The RRF score for each document: RRF(d) = 1/(k + rank_dense(d)) + 1/(k + rank_sparse(d)), where k = 60 is the default constant. The formula accumulates rank-position rewards rather than raw scores — so differing score scales across the two systems introduce no distortion.

hybrid_search.py 
# Reciprocal Rank Fusion — provider-agnostic implementation
from collections import defaultdict

def rrf_fusion(dense_results, sparse_results, k: int = 60) -> list[dict]:
    """Merge two ranked lists using Reciprocal Rank Fusion.

    Args:
        dense_results:  list of {'id': str, 'text': str, ...} ordered by dense rank
        sparse_results: list of {'id': str, 'text': str, ...} ordered by sparse rank
        k: smoothing constant (default 60, rarely needs tuning)
    Returns:
        Merged list sorted by descending RRF score.
    """
    scores: dict[str, float] = defaultdict(float)
    docs: dict[str, dict] = {}

    for rank, hit in enumerate(dense_results, start=1):
        scores[hit["id"]] += 1.0 / (k + rank)
        docs[hit["id"]] = hit

    for rank, hit in enumerate(sparse_results, start=1):
        scores[hit["id"]] += 1.0 / (k + rank)
        docs.setdefault(hit["id"], hit)

    return sorted(docs.values(), key=lambda d: scores[d["id"]], reverse=True)


# Qdrant native hybrid search (dense + sparse BM42 / SPLADE)
from qdrant_client import QdrantClient
from qdrant_client.models import (
    Prefetch, FusionQuery, Fusion,
    NamedVector, NamedSparseVector, SparseVector,
)

client = QdrantClient(url="http://localhost:6333")

def hybrid_query(query_text: str, embedder, sparse_encoder, top_k: int = 10):
    dense_vec = embedder.encode(query_text).tolist()
    sparse_vec = sparse_encoder.encode(query_text)   # returns indices + values

    results = client.query_points(
        collection_name="knowbase",
        prefetch=[
            Prefetch(
                query=NamedVector(name="dense", vector=dense_vec),
                limit=top_k * 2,
            ),
            Prefetch(
                query=NamedSparseVector(
                    name="sparse",
                    vector=SparseVector(
                        indices=sparse_vec.indices,
                        values=sparse_vec.values,
                    ),
                ),
                limit=top_k * 2,
            ),
        ],
        query=FusionQuery(fusion=Fusion.RRF),  # server-side RRF
        limit=top_k,
    )
    return results.points
